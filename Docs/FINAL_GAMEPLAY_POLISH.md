# 이안 키우기 최종 플레이 개선

Unity 6000.6.8f1, macOS Editor. 프로젝트 복사본에서 실제 Game View와 게임 서비스를 실행했다. 새 게임마다 격리된 저장 슬롯을 사용했다.

## 첫 성장

첫 성장은 0세에서 1세로 넘어가는 M001 보상 수령이다. 걷기가 열리는 시점은 1세, 혼자 외출하는 시점은 7세다.

| 같은 절차로 새 게임 3회 | 변경 전 중앙값 | 변경 후 중앙값 |
|---|---:|---:|
| 새 게임 시작부터 M001 수령까지 | 10.53초 | 5.23초 |
| 첫 돌봄 입력부터 M001 수령까지 | 8.40초 | 3.11초 |
| 아기 침대에서 수면 후 조작 복귀 | 4.06초 | 1.66초 |
| 식사 또는 수분 돌봄 한 번 | 2.16초 | 0.72초 |
| 수행한 돌봄 / 미션 보상 수령 | 3회 / 1회 | 3회 / 1회 |

세 번의 시작→성장 측정값은 변경 전 10.82 / 10.51 / 10.53초, 변경 후 5.62 / 5.23 / 5.23초였다. 출생 안내의 고정 대기, 실제 침대 메뉴의 수면·식사·수분 버튼, 실제 미션 수령 버튼을 포함한다. 자동 입력으로 측정해 **게임이 요구하는 대기는 50.3% 줄었다**. 사람이 문구를 읽고 메뉴를 찾는 시간은 별도다. 식사→수분→수면 순서도 새 슬롯에서 확인했다.

0세 가족 돌봄에만 짧은 연출 시간을 적용하고, 먹거나 마신 뒤에 재생되던 기상 연출을 제거했다. 수면 후 기상, 시뮬레이션 시간, 상태 변화, 보상과 이후 연령의 성장 조건은 기존 경로를 사용한다. 돌봄 중 같은 입력을 다시 보내도 거절됐고, 종료 후 조작이 복구됐다.

## NPC 충돌과 이동

| 재현한 문제 | 변경과 재검사 |
|---|---|
| 정적 Rigidbody2D가 붙은 가구가 빈 바닥으로 판정됐다. 격자점 사이의 얇은 벽도 놓칠 수 있었다. | 기존 격자 탐색의 연결 구간과 실제 보행을 반경 0.22의 발 충돌 범위로 검사한다. 정적 바디, 얇은 벽, 이동 장애물, 트리거를 검증하는 개발 시나리오 `world/npc-footprint`를 추가했다. |
| 착석·기립 직후 일정 시간은 옆 가구나 문까지 통과할 수 있었다. 공유 소파에서는 예약 오브젝트와 실제 가구가 달랐다. | 접근점까지 일반 보행을 하고 정렬 중에는 해당 좌석의 가구만 예외로 둔다. 같은 좌석으로 일정이 바뀌는 중에 이전 예약 해제가 새 예약까지 지우던 경우도 수정했다. |
| 의자를 옮겨도 가구 수가 같아 예전 경로를 계속 사용했다. | 실제 가구 배치가 바뀌면 경로를 다시 계산한다. 구매한 의자를 옮기는 테스트에서 기존 위치가 비고 새 위치가 막혔다. |
| 닫힌 문 안의 저장 좌표와 화면 밖에서 들어오는 주민이 문짝과 겹칠 수 있었다. | 막힌 복원 위치는 주변의 빈 보행 지점을 찾는다. 입장 주민은 문이 열린 뒤 등장한다. 문 사용자 두 명 중 한 명이 떠나도 열려 있고, 마지막 사용자가 지나가면 충돌이 복구되는 것을 확인했다. |
| 도시에서 귀가를 안내하는 골목 표지의 접근점이 보도 밖에 있었고, 보도로만 당겼을 때는 표지 받침과 겹쳤다. | 받침 옆 보도에 접근점을 배치했다. 실제 플레이어가 이 지점에서 골목으로 이동해 집으로 돌아왔다. |
| 휴게석과 생활 소품 중 일부는 그림은 있지만 발이 닿는 충돌 영역이 없었다. | 편의점·카페 직원 의자, 금융·부동산의 수납장과 전시물 받침, 가정의 빨래 바구니와 식탁 의자에 바닥 점유 범위를 맞췄다. 빨랫감을 옮기는 생활 동선도 바구니 옆으로 조정했다. |
| 점심에 손님 옆을 지나려던 편의점 직원이 휴게석을 예약한 채 서 있었다. 처음 수정한 뒤에도 재현됐다. | 발자국의 양 끝과 별개로, 두 점을 잇는 구간과 다른 주민 사이의 최단 거리를 검사했다. 예약한 의자의 접근점까지 우회한 후 착석·휴대폰·음료 동작을 관찰했다. 경로 양 끝이 비어 있고 가운데만 손님과 스치는 상황을 회귀 테스트로 추가했다. |
| 도시 인구를 갱신할 때 상점으로 향하던 행인이 화면 밖에서 집으로 돌아갔다. 횡단보도 직선 경로를 단순화하면 마주 오는 사람의 경로와 중앙에서 일치했다. | 이미 출발한 행인은 출입구까지 이동시켰다. 양쪽 보도에서 건너는 경로에는 진입점과 출구를 두어 중앙에서 0.84의 간격을 확보했다. 차량 4대·5대가 각각 운행하는 두 시각에 어머니와 행인이 보행 신호를 기다리고 차로를 건너 실제 상점 문으로 진입했다. |

화면에 있는 NPC가 외부 충돌체와 겹치면 개발 빌드에서 주민 ID, 방, 행동, 목표, 경로 지점과 충돌체를 기록한다. 같은 주민의 경고는 최소 15초 간격이다. 벽 윗마감, 벽걸이 선반, 표지판 글자, 바닥 매트, 접촉 그림자까지 이동 장애물로 만들지 않았다.

[부모님 집·회사·학교·상점·도시 Game View](FinalGameplayPolish/NPC-QC.jpg)

가족의 두 침실·거실·주방·욕실과 회사·학교·상점·도시·금융·부동산까지 11개 공간에서 입장 위치와 상호작용 접근점 사이의 길을 검사했다. **98개 중 98개에 경로가 있었고, 관찰한 일반 보행 구간에서 다른 고정물 관통은 0건**이었다. 부모 침실의 수면, 거실 청소 후 소파 착석, 주방 설거지, 학교·회사·상점 휴게석도 확인했다. 욕실에는 표본 시각에 NPC가 없어 접근 경로와 플레이어 출입으로 검증했다.

## UI와 진행 흐름

- 평소 HUD에는 시계, 현금, 생존 게이지, 미션 이름·진행도와 현재 할 수 있는 행동 한 줄이 남는다. 걷기 안내는 55자에서 14자로 줄었다. 안내 카드의 물음표로 도움말을 열 수 있고, 추천 행동을 선택하면 위치와 설명을 볼 수 있다.
- 근접 상호작용은 입력과 동사를 표시한다. 출입할 수 없을 때는 이유를 표시한다. NPC 머리 위 상태는 가까운 상호작용 대상에게만 보인다.
- 인벤토리의 반복 설명을 줄이고 아이템 정보와 비교 수치를 남겼다. 구매 가격, 확률, 루비 잔액, 법적 고지는 해당 화면에서 확인한다.
- 입력을 수락한 프레임에 행동명을 표시한다. 닫는 중 다시 연 창은 현재 투명도에서 전환한다. 반복 일반 알림을 억제하고 상태 변화 수치의 이중 기호를 줄였다.
- 장면 입장 때 모든 TMP 텍스트를 강제로 재분석하던 처리를 제거했다. 배치 실행에서는 렌더링 프레임을 기다리지 않고 입장을 마친다.

도시 입장 화면을 다시 보니 위치명이 상태창·지도·알림에 겹쳤다. 위치는 상태창에 한 번 표시하고 지도에는 ‘지도 열기’를 배치했다. 네 비율에서 지도를 열고 닫은 뒤 이동이 복구됐다.

일반 Game View에서 24개 화면·상태를 열었다. HUD·도움말·미션·인벤토리는 1920×1080, 1680×1050, 1080×2340, 1768×2208에서 다시 열었다. 검사한 활성 TMP 중 잘림 판정은 0건이었다. 메인 메뉴는 실제 화면 캡처로 확인했고, 자동 텍스트 수집기의 해당 루트에는 TMP가 없었다.

## 실제 플레이 검증

| 구간 | 확인한 결과 |
|---|---|
| 새 게임 | 먹기·마시기·수면 도중 같은 입력을 반복해도 한 번씩만 처리됐다. M001을 수령하면 1세가 되어 걸을 수 있고, 혼자 외출하는 권한은 잠겨 있었다. |
| 가족 생활·등교 | 부모님과 대화한 뒤 이동이 복구됐다. 식탁 의자에서 식사하고 일어선 뒤 욕실, 현관, 골목, 도시, 학교를 거쳐 도시로 돌아왔다. |
| 독립 생활 | 독립 집에서 회사로 출근해 지원·면접·근무를 진행했다. 급여를 받은 뒤 상점에서 빵 하나를 구입했고, 가격만큼의 현금 차감과 수량 증가를 확인했다. 집에서 잠들고 깨어난 뒤 저장·불러오기로 나이·현금·직업·거주지를 복원했다. |
| 출입과 입력 복귀 | 위 연속 실행에서 서로 다른 문 16개를 총 19회 사용했다. 각 도착지에서 조작 가능 여부를 확인했다. 접근할 때는 실제 플레이어 이동 모터를, 문 앞에서는 일반 상호작용 진입점을 사용했다. |

차량 신호를 확인하지 않고 계속 전진시키던 자동 보행은 차로에서 멈췄다. 같은 위치에 키보드 입력을 보내 차량 충돌체가 전진을 막는 것과 뒤로 걸어 나올 수 있는 것을 재현했다. 보행 신호와 차량 통과를 확인한 뒤 건너는 절차로 통합 경로를 재검사했다.

학령기와 성인 구간은 같은 테스트 세이브에서 7세·19세, 독립 보증금, 지원 가능한 능력치와 면접 난수를 준비했다. 급여 지급, 구매 및 수면은 일반 게임 동작으로 실행했다. 회사 휴게실은 사무실 안에 있다. 회사의 프린터 전용 상호작용은 현재 구현에서 확인되지 않아 별도 행동 판정에서 제외했다.

## 회귀 검사와 검증 범위

- Unity Test Framework PlayMode **11/11 통과**. QA 패널이 첫 외출 테스트의 실제 게임 입력을 가로채는 경우와, 일시적인 Bootstrap 씬을 QA 복귀 위치로 잡는 테스트 시작 경쟁 조건도 고쳐 전체 묶음을 다시 실행했다.
- 개발 QA 레지스트리 160개 중 142개 통과, 6개 수동 판정, 11개 기존 미구현, 1개 격리 슬롯 원본 부재였다. 미구현은 M039와 M051~M060이다. 이 수치는 이번 네 영역 외의 기존 게임 기능까지 포함한다.
- 모바일·폴더블은 Unity Game View의 화면 비율로 확인했다. 실기기 터치, 실제 게임패드와 신규 이용자의 자유 플레이 시간은 **NOT VERIFIED**다.
- 별도로 원본에서 복사한 2세·19세 저장을 각각 두 번 읽었다. 나이, 활성 미션, 수령한 미션 ID 목록, 현금, 루비가 두 번 모두 보존됐다. 기존 에디터·플레이어 자동 저장과 백업 4개의 SHA-256도 재확인했다.
- Unity Input System 가상 장치로 0세 스틱 보행 차단, 패드 오른쪽 버튼으로 수면 취소, 1세 키보드 보행, 미션 창의 이동 차단, Esc로 닫은 뒤 조작 복귀를 확인했다.
- 일부 격리 복사본을 열 때 Unity Editor의 검색 인덱서에서 예외가 기록됐다. 호출 위치는 에디터 시작 단계의 `SearchDatabase.EnumerateAll`이다. 이어진 게임 동작과 저장 복원 검사는 통과했다.
- 보행 검사는 지정 시각의 실내와 도시, 가구 재배치와 저장 복원 사례를 대상으로 한다. 수면·좌석에서는 본인이 사용하는 가구와 포즈가 의도적으로 겹치는 구간을 구분했다.
