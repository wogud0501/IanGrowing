## 범위와 판정 방법

프로젝트 자체 씬 28개를 열어 구조를 검사했다. 현재 일반 플레이의 공간은 룸 카탈로그에 등록된 16개다. 편의점·카페·가구 매장은 한 건물의 서로 다른 구역이고, 공원 역할의 광장 벤치는 도시 씬에 있다. 병원 씬이나 병원 입구는 없다. 부모님 집은 거실·주방·욕실·부모 침실·이안 방이 각각 별도 룸이다.

- Scene View에서 전체 구조·회전·집기 위치를 보고 Game View에서 실제 카메라와 플레이어 크기로 다시 비교했다. [주거 Scene View](WorldRealism/HomesSceneView.jpg) · [주거 Game View](WorldRealism/HomesGameView.jpg) · [도시·시설 Scene View](WorldRealism/CitySceneView.jpg) · [도시·시설 Game View](WorldRealism/CityGameView.jpg)
- 양방향 연결 15쌍을 실제 플레이어 모터로 보행했다. 통행에는 E 입력과 같은 상호작용 진입점을 사용했다. 문 열림, 도착 씬, 반대편 출현점의 충돌, 입력 복구를 별도로 기록했다. 골목과 도심 사이 보행로 2방향에는 문짝이 없다.
- 룸별 상호작용점·직원 전용 지점·미구매 가구 후보 167개를 수집했다. 활성 오브젝트 152개의 접근점에서 보행 경로를 구했고, 반경 0.22 안에서 접근을 막는 고정 충돌체는 0개였다. 이 중 플레이어 상호작용 컴포넌트가 활성화된 지점은 86개였다. 자세와 행동 결과는 아래에 기재한 대표 동작을 실연했다.
- 자체 씬 28개에서 누락 MonoBehaviour, 끊긴 Prefab, SpriteRenderer의 끊긴 Sprite·Material 참조가 각각 0개였다. 활성 스프라이트의 미세한 비정수 직각 회전 및 검사 대상 기본 오브젝트 이름도 0개였다. 실제 건물 외형과 스프라이트에 이미 그려진 방향은 Game View에서 따로 확인했다.
- 활성 빌드 프로필은 Windows이고 활성 씬은 25개다. 빌드 목록에는 부팅·메뉴, Battle·StockMarket, 이전 라우터용 Home·School·City·Workplace·LifeWorld, 현재 룸 16개가 포함된다. MainGame·MainGame2D·HomeShowcase는 비빌드 소스이며 SampleScene은 비활성 외부 샘플이다.

## 휴식과 가족 생활

기존 일정과 주민 스케줄러에서 좌석을 예약한다. 이동 중에는 보행 상태를 유지한다. 착석 지점에 도착하면 좌석을 점유하고, 같은 구역의 빈 대체 좌석도 사용할 수 있다. 휴게 동작은 앉아 있기·음료·휴대전화로 변한다. 퇴석할 때 일어선 다음 자리를 돌려준다. 점심과 짧은 근무 휴식은 각각 다른 일정이다.

집안일은 보관점, 작업점, 회수점으로 구성했다. 거실 청소는 날짜에 따라 쓸기·대걸레·진공청소로 순환한다. 다른 시간에는 식탁 닦기, 설거지, 빨래 바구니 운반, 쓰레기봉투 정리를 한다. 작업자는 대상 하나를 선점하며 손 도구, 자세, 방향, 이동, 상태 문구가 같은 행동을 따른다. 빈 좌석이 생길 때까지 바닥에서 쉬는 상태를 허용하지 않는다. 부모의 기존 직업 데이터는 둘 다 가족 돌봄 역할이고 별도 고용처가 없다. 독립 집에는 상시 거주 NPC가 없다.

## 공간상의 예외

- 상점과 카페 직원은 같은 건물의 후면 공간에 각자의 좌석을 쓴다. 금융·부동산 직원 공간은 개방형 칸막이로 구분한다. 별도 직원 통제문이나 신규 씬을 추가할 필요가 없었다.
- 독립 집 초기 상태에는 주방 가전이나 소파가 없다. 집안일의 빨래와 쓰레기는 실내 운반·정리까지 표현한다. 세탁기 전체 사이클과 외부 수거 작업은 모델링 범위 밖이다.
- 집과 학교·회사 간의 거리, 실내 문 너비는 기존 게임 보행과 픽셀 카메라에 맞춘 축척이다. 이동 검증은 실제 플레이어 모터·물리·상호작용 경로를 프로그램으로 구동한 Editor Play Mode 기준이다.
