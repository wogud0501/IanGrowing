# 이안 키우기 로컬 오류 기록

타이틀과 게임 내 **설정 → 편의 → 진단 및 오류 기록**에서 최근 기록과 상세 정보를 확인한다. 화면 이상처럼 예외가 없는 문제는 재현 직후 **보고서 만들기**를 사용한다. 목록에서 보고서를 고르면 내보낼 TXT 전체를 볼 수 있다. 확인 후 사용자가 파일을 전달한다. 개발자에게 자동 접수되는 기능은 없다.

## 저장 및 조회

기본 경로는 `Application.persistentDataPath/Diagnostics`다. 프로젝트의 앱 식별자와 플랫폼에 따라 상위 경로가 달라진다.

| 위치 | 내용 |
|---|---|
| Errors/ERR-…/report.txt, report.json | 같은 사건의 읽기용·구조화 사본. 같은 디렉터리에서 둘 다 작성한 뒤 이름을 바꿔 공개 |
| Sessions/*.session | 실행별 1바이트 표시. 전경/백그라운드를 구분하고 정상 종료 때 정리 |
| Exports/ | 사용자가 선택한 보고서의 공유용 TXT. 게임 안에서 삭제하면 여기에 있는 해당 사본도 삭제 |

Windows·macOS는 내보낸 파일의 폴더를 연다. Android는 읽기 전용 URI로 공유하거나 시스템 파일 선택기에서 위치를 지정한다. iOS는 iPad 팝오버 위치를 지정한 시스템 공유 시트를 연다. 공유를 취소할 수 있다. 다른 앱에 전달하거나 다른 경로에 저장한 파일은 해당 위치에서 관리한다.

## 수집 및 한계

- Error, Assert, Exception에만 응답한다. 일반 Log와 Warning은 파일로 만들지 않는다. 임의의 콘솔 메시지는 허용 목록에 있는 내용이나 예외 유형만 남긴다. 호출 인수와 경로의 상위 디렉터리를 버린다.
- Unity 다중 스레드 콜백은 순수 관리 코드만 사용한다. 발생 당시 캐시한 Scene·플랫폼·빌드와 게임 나이·날짜·행동, 최근 40개 기능 이벤트를 복사한다. 최대 16건 대기, 동일 메시지/스택 60초 억제, 1분에 서로 다른 지문 최대 64건. 플레이 중 한 프레임에 최대 2건을 기록하고 일시중지·종료 시 대기열을 비운다. 강제 종료 시 아직 쓰지 않은 건은 유실될 수 있다.
- 생성·목록 열기·실행 중 주기적으로 14일, 20건, 10 MiB 한도를 적용한다. TXT와 JSON 한 쌍은 1건이다. 저장 실패는 진단 경로에서 처리하고 게임 Save에 쓰지 않는다.
- 첫 번째 게임 코드 프레임을 우선 표시한다. 빌드에서 줄 번호가 생략되면 Unavailable을 표시한다. Android/iOS는 IL2CPP, Standalone은 프로젝트 기본 백엔드를 사용한다. IL2CPP 사용 시 해당 타깃의 MethodFileLineNumber 설정을 적용한다. 스크립트 디버깅은 별개다. 릴리스마다 빌드 GUID와 일치하는 dSYM, Android symbols, Windows PDB 및 IL2CPP 빌드 산출물을 접근 통제된 개발자 저장소에 보관해야 한다. 사용자 보고서에는 심벌 파일을 포함하지 않는다. [Unity IL2CPP 스택 트레이스](https://docs.unity3d.com/6000.0/Documentation/Manual/il2cpp-managed-stack-traces.html)
- 전경 세션의 정상 종료 표시가 없으면 재실행 타이틀에서 한 번 안내한다. 이 표시는 중단 원인을 판별하지 않는다. 메모리 부족, GPU 오류, 전원 차단, OS 프로세스 종료는 C# 콜백까지 도달하지 않을 수 있다.
- Windows에서는 별도로 Unity 크래시 폴더를 열 수 있다. 네이티브 덤프에는 메모리 내용이 들어갈 수 있어 게임의 필터와 보존 정책에서 제외한다. Android와 iOS의 시스템 크래시 기록은 OS가 관리한다. iOS 시스템 진단 보고서는 설정의 분석 데이터에서 별도로 확인할 수 있다.

## 오류 재현

Development 데스크톱 Player에 `-ian-test-local-report`를 주면 시작 시 실제 null 역참조를 잡아 5회 로깅하고, 필터 시험용 Error와 Assert를 발생시킨다. 게임 진행을 초기화하지 않는다. 이 코드는 릴리스 빌드에서 제외된다. 결과 예시는 [QA 기록](ERROR_REPORT_QA.md)에 있다.
