# Stage A / B 검증 기록

## 구현 범위
Stage A 감사와 Home ↔ School 버티컬 슬라이스를 구현했다. 상업용 최종 그래픽 완성 판정은 유보한다. Home·School 신규 배경, 남색/황동 9-slice 프레임, 소형 HUD, 기존 네 메뉴와 모달, 실제 행동 결과·성적 통지표, 픽셀 호흡/환경 효과, 비동기 전환이 실제 씬에서 동작한다. City·Workplace 아트 전면 제작은 Stage C에 남겨 두었다.

## 실행 도구 / 환경
- Unity 6000.6.7f1 / URP 17.6.0 / Android 활성 빌드 타깃. 공식 Unity 플러그인의 관련 스킬 문서를 읽고 적용했다.
- CLI beta.13 실행 가능. Editor descriptor 접근 거부로 연결 불가; 업데이트 확인 SSL 실패. 동일 프로젝트 MCP 연결을 확인하고 Editor 작업에 사용했다. beta.17 알림은 기록했으며 CLI를 임의 업데이트하지 않았다.
- built-in imagegen으로 배경 2종·UI 프레임을 생성하여 프로젝트에 실제 복사/임포트했다. 외부 에셋 팩을 다운로드하지 않았다.
- 작업 전 Git 체크포인트 `125484c`. 작업 도중 사용자 커밋 `3ce55ef`가 생겼으며 이를 되돌리지 않았다.
- 종료 시 Play Mode를 중지하고 Home 씬을 열어 둔다. 검증용 runInBackground 설정은 원래 false로 복원한다.

## 콘솔 및 성능
- 최종 42개 검증 후 C# compilation 실패 플래그 false, 해당 실행 구간 Console error/warning **0건**을 확인했다.
- 중간 점검에서 additive 활성화 순간 EventSystem 중복 경고를 발견했다. 이전 씬의 입력 모듈/EventSystem/Camera/AudioListener를 목적지 활성화 직전 중지하고, 실패 복귀 시 복원하도록 수정했다.
- Play Mode 종료 때 기존 Phase23Presenter가 파괴 중인 버튼을 갱신하는 오류도 발견했다. 표현 계층의 OnDisable 구독 해제와 파괴 참조 방어를 추가했다. 모델/행동/저장 규칙은 바꾸지 않았다.
- 별도 기존 Unity AI 서비스에서 generators.ai.unity.com `NoSubscription` 오류가 관측됐다. 이번 아트 생성에는 그 서비스를 사용하지 않았다.
- 작업 전 MissionCondition 재귀 직렬화 깊이 경고를 관측했다. 게임 데이터 스키마를 바꾸지 않았다.
- Editor 정지 장면 표본: Atlas 적용 전 22 draw calls, 적용 후 Home 14 draw calls / 1084 triangles. 기기 성능 벤치마크가 아니며 GPU/열/배터리 개선 수치로 해석하지 않는다.
- 환경 효과 8Hz 한 스케줄러, 최대 10개 기존 SpriteRenderer 재사용. 낮음 4개 / 높음 10개 / 끄기 0개. 파티클 시스템을 만들지 않아 별도 파티클 풀이 필요하지 않다.
- Home 씬 의존성 검사에서 `_Source.png` 생성 원본 참조가 0개였다. 런타임 씬은 경량 파생본을 참조한다.
- Windows 플레이어 빌드·Android APK/AAB·실기기·터치 하드웨어·장시간 메모리/열 테스트는 **미실행**.

## 남은 품질 제한
- 픽셀 배경은 AI 원본을 640×360으로 nearest 샘플링한 제작 후보다. 모든 픽셀 클러스터가 수작업 픽셀 그리드라는 의미가 아니다.
- 공식 이안은 원래 디자인을 유지했다. 배경과 캐릭터의 원본 해상도/묘사 방식 차이가 남아 있다. Blink/Eat/Walk 등의 새 프레임을 제작했다고 주장하지 않는다.
- 가구/원경/NPC 대부분은 배경에 구워져 있다. 모니터/햇빛 보조 레이어·glint/dust·이안 호흡만 독립 동작한다. 커튼/NPC/차량/일기 변화의 완전한 다층 애니메이션은 미제작.
- 전환은 프로필/셔터/입장·퇴장 훅까지 구현했다. 전용 문·등교·엘리베이터 스프라이트 컷신과 전환 사운드는 미제작.
- UI는 기존 9-slice/아이콘/포커스·스택 구조를 재사용했다. 모든 요청 컴포넌트를 각각 새 독립 프리팹으로 제작한 것은 아니다.
- Windowbox 정수 우선 정책으로 640×360의 정수 배율이 잘 맞지 않는 창에는 여백이 생긴다. 세로 화면과 720px 미만 높이는 별도 모바일 레이아웃 검토 대상이다.
