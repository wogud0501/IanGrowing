# 모바일 HUD 검증

대화에 원본 스크린샷 파일이 첨부되지 않아, 기존 빌드 상태의 영아 방을 1080×2340 Game View에서 촬영하고, 변경 후 같은 시각·장소·나이로 다시 촬영했다. 세 번째 패널은 보행 해금 후다. [변경 전후](VisualNPCMobile/Mobile-Before-After.jpg) · [네 화면 비율](VisualNPCMobile/Mobile-Viewports.jpg)

| 항목 | 재생 결과 |
|---|---|
| 휴대전화 세로·가로 | 1080×2340, 2340×1080에서 이동 패드·가방·메뉴·사용·뛰기·상태 게이지 사이에 겹침이 없었다. |
| 태블릿·폴더블 | 1536×2048, 1768×2208에서 같은 여섯 영역의 화면 좌표를 검사했다. 태블릿과 펼친 화면에서도 하단 조작 위치가 유지됐다. |
| 노치·시스템 바 여백 | 첫 시험에서 사용 버튼이 모의 안전 영역을 벗어났다. 터치 루트가 속한 캔버스의 좌표로 안전 영역을 변환하도록 수정했다. 1768×2208 화면에 좌우 96, 하단 88, 상단 80픽셀을 제외한 재시험을 통과했다. |
| 입력 안내·취소 | 터치에서 상호작용은 ‘사용’으로 표시한다. 취소 가능한 행동 중 같은 자리가 ‘취소’로 바뀐다. 가방 버튼을 통해 실제 인벤토리가 열리고 월드 입력이 잠기는 것을 확인했다. |
| 영아기 | 이동 권한이 없는 0세에는 조이스틱과 뛰기 버튼이 숨는다. 돌봄 상호작용과 보조 메뉴는 사용할 수 있다. |
| HUD 피드백 | 허기·수분·체력·멘탈은 아이콘과 게이지로 표시한다. 일상적인 수치 변화는 해당 게이지에서 반응하고 수치는 상태창에서 확인할 수 있다. 저장 알림은 사용 버튼과 떨어뜨렸다. |

조이스틱의 터치 영역은 132, 보이는 원판은 124, 손잡이는 52 캔버스 단위다. 이동 범위는 40이다. 가방·메뉴는 작은 보조 버튼으로 묶었고 사용은 아래쪽에 고정했다. 기존 무채색 UI와 Input System의 월드 이동 액션을 재사용했다.

**독립 실행 입력 회귀.** macOS 개발 빌드에서 Input System에 손가락 누름·연속 드래그·뗌을 전달했다. 첫 시험에서 스틱에 터치가 닿아도 이동값이 0이었다. 조이스틱이 기존 UI 입력 모듈에서 해당 손가락의 드래그를 받도록 바꿨다. 같은 시험에서 가상 스틱은 (1, 0), 이안의 위치는 (500.00, 4.40)에서 (502.18, 4.36)으로 바뀌었다. 영아 입력 제한과 기상 뒤 월드 조작도 확인했다. macOS 창을 강제로 재활성화한 별도 실행에서는 드래그 도중 스틱 방향이 한 차례 달라졌다. 창이 전면에 유지된 재시험에서 수평 입력이 재현됐다.

**기기 범위.** 레이아웃은 Unity Game View에서, 터치 이벤트에서 플레이어 이동까지는 macOS 독립 실행 빌드에서 시험했다. 연결된 실제 Android/iOS 기기가 없어 엄지 도달성, 실기기의 노치·시스템 제스처, 발열은 미검증이다.
