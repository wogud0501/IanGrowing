# 부모님 집 공간 복구 계획 — 실제 적용 기준

원인: `FamilyLifeSetup.BuildFamilyLife()`가 Room 한 개를 만든 뒤 침대3개와 식탁3개를 좌표 루프로 배치했다. 런타임에서 기존 방을 지운 문제가 아니라, Editor 생성 데이터 자체에 방과 벽/출입구 정의가 없었다. 이전 시안은 폐기하지 않고 Git 작업/백업으로 남기되, 실제 생성 결과는 아래 권위 있는 평면으로 교체한다.

LifeWorld 단일 Scene, 가족 집 한 구역 안에서 실제 물리 벽과 문으로 나눈다. 각 침실마다 별도 Scene을 만들지 않는다.

```text
북쪽
┌────────────────┬────────────────┬────────────────┐
│ 부모님 침실     │ 이안의 방       │ 독립 욕실      │
│ 옷장·부부 잠자리│ 영아 침대/침대  │ 샤워·세면·변기 │
│ 협탁·통행 공간 │ 개인 수납       │ 타일 바닥      │
├────── 문 ──────┼────── 문 ──────┼────── 문 ──────┤
│                │                                 │
│ 거실           │ 주방                            │
│ TV ↕ 소파      │ 싱크 ─ 조리대 ─ 냉장고          │
│ 가족 휴식      │       작업 통로                  │
│        통로 →  │    하나의 가족 식탁 / 세 좌석    │
│   현관         │                                 │
└────────────────┴─────────────────────────────────┘
남쪽
```

- 가족 집 가용 바닥 24×18; 부모/이안/욕실은 각각8×8, 남쪽 거실/주방은 각각12×10.
- 침실/욕실 전면 y=1에 각1.8 폭 출입구; 나머지는 실제 벽 Collider. 좌우 침실 경계 x=-4/+4. 거실/주방은 x=0 벽과 넓은 통로로 구분.
- 부모님 침실 안에 기존 부모 잠자리2개를 두되, 이안 잠자리는 벽 너머 별도 방으로 이동. 아기 침대는 신생아 전용 이미지/돌봄으로 표시. 향후 부부 침대 아트 교체가 가능한 고유 앵커를 유지한다.
- 공동 식탁은 단일 스프라이트/Collider와3개 점유 앵커를 사용한다. 기존 작은 테이블3개 이미지/Collider는 제거한다. 실제 점유 인원 마스크에 해당하는 합성 프레임만 표시한다.
- 주방 조리대·싱크·냉장고는 같은 벽면 작업 구역에 배치하고, 냉장고 문 개방/접근 공간과 식탁 뒤 이동 통로를 확보한다.
- 욕실은 집 평면 안으로 이동한다. 과거 family-bathroom 저장 위치는 가족 집 안 욕실 위치로 안전하게 매핑하며 내부 저장 식별자를 임의 삭제하지 않는다.
- 실제 평면 데이터: `FamilyHomeArchitecturePlan` / `Data/Phase26/FamilyHomeArchitecture.asset`; 생성 코드: `Editor/FamilyArchitectureSetup.cs`.
- 평소 카메라는 이안과 근처 공간을 보여준다. 전체 평면 캡처만 QA에서 일시적으로 넓게 보여주고 원래 카메라를 복구한다.

검증 예정: 각 방 포함/벽·문 Collider·문 양방향 개폐·침실→주방 실제 NPC 도보·냉장고/조리/공동 식사·저장 호환·기존 주요 문 회귀. 실행하지 않은 항목을 PASS로 기록하지 않는다.
